# Space RPG 项目墓志铭

> 2026-04-10 ~ 2026-04-16，七天。
>
> 一个冲动造轮子的故事。

---

## 起因

某天觉得：AI驱动的文字RPG，市面上没有做对的。市面上有的都不够沉浸。我要自己做。

于是口述了一份方案，豆包帮忙结构化，DeepSeek交叉验证了三轮，GLM再过了一遍——结论是：**可行，架构清晰，动手吧**。

## 造了什么

七天内，从零搭建了一套完整的系统：

| 层 | 做了什么 |
|----|---------|
| 架构 | 双层状态（state.json + 幕文件检索），本地持久化，零服务器 |
| 工具 | 8个核心工具（战斗/资源/技能/航行/交易/时间/检索/休息条件），工具独占写入 |
| 幕间 | 三级休息机制（完整/简易/紧急），有条件触发，不是随时可用的技术操作 |
| AI对接 | 6个平台（DeepSeek/OpenAI/Claude/Qwen/GLM/自定义），指数退避重试，多格式响应解析 |
| 界面 | 沉浸式船载终端风格，统一终端科幻CSS系统，4个页面全部对齐 |
| 一致性 | 后处理校验器实时验证AI输出，状态快照可回溯，关键词索引不依赖AI |

最终交付物：13个JS模块、4个HTML页面、3个CSS文件、13份设计/审查/错误文档。

一份**从架构设计到工程实现到测试验证**的完整记录。

## 做对了什么

几条从实战中长出来的铁律，比任何教科书都真实：

1. **AI只叙事，工具只算数。** AI绝不碰游戏机制数值——这是AI+游戏系统的核心矛盾和解法。
2. **永远不信任AI返回JSON。** 严格prompt约束 + 后解析校验 + 降级兜底，三层防御。
3. **占位符必须标记TODO，集成时逐一验证桥接。** 否则功能看起来完成了，实际上全是断裂的。
4. **第一天就用配置对象。** 不要指望"后面再清理硬编码"。后面通常不会清理。80个散落数值就是代价。
5. **AI方案必须裁剪。** 教科书方案 ≠ MVP方案。AI给你设计一个 RequestQueue 类，但你的RPG游戏根本不存在并发请求。
6. **端到端链路检查不可省。** AI代码审查打了4/5分，但三处HTML→JS接口断裂导致基本功能不可用。代码美学 ≠ 功能可用。
7. **AI审查的数字不可信。** "API成功率从70%提升到95%"——基准数据本身就是编的。

## 为什么停了

第七天，发现了 SillyTavern（酒馆）。

Vector Storage、Summarize、Quick Replies、Regex 扩展，加上 rpg-companion 等第三方插件——已经完整覆盖了我们自研的全部功能需求。而且生态成熟，社区活跃，不用维护。

**我们用七天造了一个轮子，然后发现别人已经造了更好的。**

这不是失败。这恰恰是造轮子的意义：你不亲自造一遍，你永远不知道为什么别人的轮子是圆的，那个轮辐的角度为什么是那个角度，为什么轴承要用滚珠而不是滑动。

## 这七天值不值

值。

不是因为产出了代码——代码已经归档，大概率不会再被运行。

值在这十条教训：

| # | 教训 |
|---|------|
| 1 | AI只叙事，工具只算数 |
| 2 | 永远不信任AI返回JSON |
| 3 | 占位符必须标记TODO |

它们会带进下一个项目。KASKAD也好，SysOps也好，或者还没出现的项目也好。
